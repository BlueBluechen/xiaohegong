# 小小河工 · AI+ 公民河流教育计划

面向 6–12 岁孩子的公民河流教育产品。以北京清河 23.6 公里干流、十座水闸为骨架，
让孩子「走到河边、动手记录、替这条河做点事」。

**完整版是一个单文件 HTML**（`小小河工.html`，约 200 KB），双击就能打开，不依赖网络。

---

## 这是什么

核心产品是**小小河工**：一个孩子领一本护照，沿清河十座闸逐站巡河、记录、盖章。
产品哲学是「以河为目标，孩子是参与者，记录是产品」——壁垒在真实内容，不在玩法。

按孩子与河的距离分成五层：

| 层 | 条件 | 做什么 | 积分 |
|---|---|---|---|
| **L0 上岗培训** | 任何地方 | 十座闸题库抽 6 道，答对 4 道过关，领护照 | 封顶 220 |
| **L1 到岸签到** | 河边 1 km | 走出门即公益 | +30，连续签到递增 |
| **L2 四宫格寻宝** | 到岸 | 按点位拍齐 4 样风物 | 每格 +15，集齐 +40 |
| **L3 现场记录** | 到岸 | 每站一个观测任务，**唯一进数据集的一层** | +25/条（有照片 +30） |
| **L4 守点双周回访** | 认领 + 复访 | 建立时间序列（P1 才开放） | — |

L3 提交后会印一张**拓印纪念卡**：有照片的印成对半卡（上半是孩子自己的原片，下半是
拓印插画 + 一个中文词），没照片的印成纯拓印图。这张卡是「拍照」的正向回报——
照片上传率是产品的护栏指标之一。

职级：见习河工 0 / 巡河员 100 / 河段长 250 / 民间河长 500。

主页分三个 Tab，按「是否需要到场」划分：

- **探索**——不依赖定位：上岗考核、十座闸图鉴、随手拍、河边正在发生（别人的记录）
- **巡河**——必须到场：签到、四宫格、现场记录、守点、足迹图
- **我的**——护照、等级、统计、拓印纪念卡、已收录知识卡、我的记录、自然笔记

## 部署

当前部署在**火山引擎 veFaaS**（云函数 + Serverless API 网关）。

选它而不是对象存储的原因：TOS 默认域名对 `text/html` 强制
`Content-Disposition: attachment`（会变成下载而不是预览），绑自定义域名需要 ICP 备案，暂无备案。

**线上地址**
https://spia36dgovq41agn99emn.apigateway-cn-beijing.volceapi.com

**部署步骤**

```bash
# 1. 同步主文件到部署目录
python3 deploy_prepare.py

# 2. 推代码（需先 vefaas login --accessKey xxx --secretKey xxx）
cd deploy && vefaas push --funcId c3avz9rf --outputPath ./

# 3. 触发发布
vefaas fn release --id c3avz9rf
```

**资源配置**

| 项 | 值 |
|---|---|
| 函数 | `xiaohegong` / `c3avz9rf`（native-node20，512 MB，端口 8080） |
| 启动命令 | `node server.js` |
| 网关 | `cybercultivate` / `gd5usigss60ctn1dbli3g`（serverless 型，免托管费） |
| 网关服务 | `xiaohegong` / `spia36dgovq41agn99emn`（独立域名，与同网关下其他业务隔离） |
| 路由 | `GET,HEAD /` |

**踩过的坑**

- `vefaas deploy` 不能用——它是「构建 + 输出目录」模式。传已有代码要用 `vefaas push --outputPath`
- 网关路由用 `vefaas trigger apig bind` 一条命令建（service + upstream + route 一起）
- 不要先手工 `ve apig CreateUpstream`，会和 CLI 冲突报 `DuplicatedResource`
- 两个 CLI 凭据分离：`vefaas` 用 `~/.vefaas/auth.enc`，`ve` 用环境变量。切账号要物理移走 `auth.enc` 再 `--accessKey` 登录

## 拓印体验（独立入口）

`小小河工-拓印体验.html` 是一个不需要护照的入口：写个名字就能玩，拍照 → 印成拓印卡 → 存进同一份护照。

**和主产品是同一份数据**：两边共用 localStorage `xxhg_v4`，称呼、护照编号、纪念卡全部打通。
在拓印页改名，护照上一起改；在这里印的卡，会出现在「我的 → 拓印纪念卡」。

| 形态 | 条件 | 构图 |
|---|---|---|
| **对半卡** | 上传了自己的照片 | 上半原片，下半拓印插画 + 中文词 |
| **纯拓印图** | 用内置题材 | 整张拓印插画，暖白纸底 |

**渲染有两条路**（自动选择，不用配置）：

1. **AI 重绘**（首选）——照片经 `/api/stamp` 发给服务端，调用火山方舟 Seedream 重绘成拓印插画。
   约 14 秒出图，质量接近 skill 成品。**ARK key 只在服务端环境变量里，前端永远看不到。**
2. **本地 canvas**（降级）——服务端不可用时自动退回双色网点渲染，断网也能出卡。
   这是滤镜不是重绘，质量有上限，但保证现场不白屏。

部署时要给函数配环境变量，否则 AI 路线会自动降级：

```
ARK_API_KEY   = 你的方舟 key
ARK_MODEL     = doubao-seedream-5-0-flash-260915   # 可选，默认就是它
```

**注意**：`ARK_MODEL` 必须是**账号实际开通**的模型。用 `render_stamp.py --probe` 可查。
账号没开通时会报 404；额度不足报 429（去控制台关掉「安全体验模式」的用量上限）。

批量预生成素材（现场断网兜底用）：

```bash
export ARK_API_KEY=xxx
python3 render_stamp.py 照片.jpg --subject swan -o out.png --web out-480.jpg
```

脚本带 `watermark: false`（官方关水印参数）——**不要改成 true**，否则卡上会带「AI生成」。

| 字段 | 说明 |
|---|---|
| 记录ID | `P0-0001`，人工编号 |
| 点位编号 | 1–10，对应十座闸 |
| 时间 | 2026-10-20 10:30 |
| 孩子昵称 | 化名，**不要写真实姓名** |
| 任务类型 | 水文观测 / 物种观察 / 岸线观察 / 异常通报 |
| 观测数值 | `键=值`，如 `透明度=3级`、`垃圾=少量` |

| 分级 | A·有照片 / B·无照片 |
| 注入产品 | **选「是」才会进 HTML** |
| 备注 | 拍摄条件、异常说明 |

### 实际工作流：先传照片，再补信息

传照片是最花时间的，字段可以后补。所以有两个脚本：

```bash
# 1. 看哪些只传了照片、还没补齐
python3 fill_p0.py --list

# 2. 按昵称批量补齐（同一个孩子的多条记录一次搞定）
python3 fill_p0.py --nick 哼哼 --gate 3 --type 物种观察 \
       --obs "水鸟=1只" --text "水面上一只鸳鸯，雄的" --inject

# 3. 补完注入产品
python3 build_from_p0.py --inline
```

`--inject` 才会把「注入产品」设为「是」。不加就只补字段不进产品，
适合先整理、再统一放行。

### 注意事项

- 表里现在有 3 条**格式示例**（P0-0001~0003，均 `注入产品=否`），填真实数据后删掉
- **记录ID 必须唯一**。`build_from_p0.py` 会查重，撞号会直接报错并列出是哪几个人——人工复制粘贴很容易撞号，这条拦在构建阶段比在页面里出 bug 好
- 只传了照片的记录不会进产品：缺点位、时间，构建脚本会跳过
- 照片只传 file_token，**不入 HTML**（体积与隐私）；产品里只显示 `has` 标记
- P0 记录和 demo 的 `SEED` 在代码里分开放（`p0:true`），UI 上「实测」与「历史」分开标，
  不要把演示数据和真实数据混着讲

## 技术约束（改之前先看）

- **单文件、零依赖**：不引入构建链，不用 npm 包，不用外部 CDN。要的是「断网双击也能跑」
- **视觉体系固定**：DARK `#07363C` / TEAL `#0E5C63` / GOLD `#C9A24B` / CREAM `#F7F4EC` / SEAL `#B5432F`；宋体标题 + 苹方正文
- **答题页绝不能出现题库原文**：闸名、故事都含答案线索，只能在答对后作为「老周说」出现
- **记录单向追加**：`S.recs` 永不覆盖，因为同一点位的时间序列是产品的北极星指标
- **照片只存内存**：dataURL 不写 localStorage（避免配额爆炸），只存 `has` 标记
- 所有 `render*Mod()` 必须有 `if(!box) return` 保护——结构改动后极易漏引用

## 拓印纪念卡（内容依赖）

L3 记录完成后生成一张卡，视觉语言来自外部 skill `qinghe-citywalk-stamp`
（剪纸刀刻轮廓 × 孔版半透明叠印 × 海绵拓包颗粒）。两种形态：

| 形态 | 触发 | 构图 |
|---|---|---|
| **对半卡** | 记录带照片（A 级） | 上下严格 1:1：上半原片，下半拓印插画 + 中文词，接缝锐利 |
| **纯拓印图** | 记录无照片（B 级） | 整张为拓印插画，四周暖白纸底留白 |

实现要点：

- 拓印图以 base64 内联在 `ART` 常量（4 幅：bridge / swan / sluice / reed），
  `WORDCARD` 决定十站各用哪个词、哪幅图。**换图只需替换 `ART[key]`，不用动逻辑**
- 卡只存元数据在 `S.mcards`，原片走 `PHOTO_BANK`（内存），和照片同一策略：不写 localStorage
- 文案只有中文词，**不放英文与音标**——这是产品决定，别加回去

## 记录模型

统一对象，8 个字段：

```js
{
  id, gateId, ts, type,
  obs,        // [{key, num, unit, txt}]  ← 没有它，产品就只是问卷
  evidence,   // {has, photo}
  env, observer, license,
  source,     // 'field' 进数据集 / 'explore' 只科普
  label, note, pts, seed
}
```

`obs` 是核心：`num` 可统计，`txt` 是人的话。
两个派生视图：按点位聚合（足迹图 / 站点详情）、按时间排序（时间线 / 同项对比）。

## 路线图

| 阶段 | 周期 | 过闸条件 |
|---|---|---|
| **P0 变真** | 2 周 | 5 个真孩子中 4 人能独立完成含有效数值的记录 |
| **P1 单点闭环** | 6 周 | D30 复访率 ≥40%，且 1 个点位有 ≥10 条跨时间同项记录 |
| **P2 数据可见** | 8 周 | 有机构把数据真的用进某份材料 |
| **P3 复制** | Q2 起 | 第二条河上线且不依赖原团队驻场 |

**北极星**：同点位有效记录数。

**护栏**：单条记录 ≤4 分钟、定位失败率 ≤15%、跨站完成率不作 KPI、照片上传 ≥60%。
