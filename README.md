# 小小河工 · AI+ 公民河流教育计划

面向 6–12 岁孩子的公民河流教育产品。以北京清河 23.6 公里干流、十座水闸为骨架，
让孩子「走到河边、动手记录、替这条河做点事」。

**完整版是一个单文件 HTML**（`小小河工.html`，约 200 KB），双击就能打开，不依赖网络。

---

## 这是什么

核心产品是**小小河工**：一个孩子领一本护照，沿清河十座闸逐站巡河、记录、盖章。
产品哲学是「以河为目标，孩子是参与者，记录是产品」——壁垒在真实内容，不在玩法。

按孩子与河的距离分成五层：

| 层 | 条件 | 做什么 | 积分 |
|---|---|---|---|
| **L0 上岗培训** | 任何地方 | 十座闸题库抽 6 道，答对 4 道过关，领护照 | 封顶 220 |
| **L1 到岸签到** | 河边 1 km | 走出门即公益 | +30，连续签到递增 |
| **L2 四宫格寻宝** | 到岸 | 按点位拍齐 4 样风物 | 每格 +15，集齐 +40 |
| **L3 现场记录** | 到岸 | 每站一个观测任务，**唯一进数据集的一层** | +25/条（有照片 +30） |
| **L4 守点双周回访** | 认领 + 复访 | 建立时间序列（P1 才开放） | — |

职级：见习河工 0 / 巡河员 100 / 河段长 250 / 民间河长 500。

主页分三个 Tab，按「是否需要到场」划分：

- **探索**——不依赖定位：上岗考核、十座闸图鉴、随手拍、河边正在发生（别人的记录）
- **巡河**——必须到场：签到、四宫格、现场记录、守点、足迹图
- **我的**——护照、等级、统计、已收录知识卡、我的记录、自然笔记

## 内容维护：改飞书，不改代码

十座闸的故事、题目、选项、知识卡、现场任务，**全部存在飞书多维表格**，不再硬编码。

**飞书 Base**：小小河工·内容库
https://my.feishu.cn/base/CACyb67OaaFXZPskQQtc6IDTnDc

| 表 | 内容 |
|---|---|
| 十座闸 | 10 条 × 34 字段（段位/公里/坐标/故事/题/选项/答案/提示/知识卡/任务/观测/回执） |
| 四宫格 | 40 条（10 点位 × 4 格，含拓印图 key） |
| 自然笔记 | 8 条词条 |

**日常流程**：

```
改飞书表格  →  python3 build_from_feishu.py --inline  →  HTML 自动更新
```

`build_from_feishu.py` 会拉取三张表，生成 `content.js`，并把
`GATES` / `HUNTS` / `KB` 三块常量内联回 `小小河工.html`。

**注意事项**

- HTML 里的 `GATES` / `HUNTS` / `KB` **由脚本生成，不要手改**——下次构建会被覆盖
- `MOTIF`（28 幅木刻拓印风 SVG）仍手写在 HTML 里，不归飞书管（base64 图形数据不适合放表格）
- 字段名或数量变更时，`build_from_feishu.py` 会报错并列出缺哪个字段，不会静默产出空内容

## 部署

当前部署在**火山引擎 veFaaS**（云函数 + Serverless API 网关）。

选它而不是对象存储的原因：TOS 默认域名对 `text/html` 强制
`Content-Disposition: attachment`（会变成下载而不是预览），绑自定义域名需要 ICP 备案，暂无备案。

**部署步骤**

```bash
# 1. 同步主文件到部署目录
python3 deploy_prepare.py

# 2. 部署（需先 vefaas login）
cd deploy && vefaas push --funcId c3avz9rf --outputPath ./
```

函数：`xiaohegong`（ID `c3avz9rf`，native-node20，512 MB，端口 8080）
启动命令：`node server.js`

## 技术约束（改之前先看）

- **单文件、零依赖**：不引入构建链，不用 npm 包，不用外部 CDN。要的是「断网双击也能跑」
- **视觉体系固定**：DARK `#07363C` / TEAL `#0E5C63` / GOLD `#C9A24B` / CREAM `#F7F4EC` / SEAL `#B5432F`；宋体标题 + 苹方正文
- **答题页绝不能出现题库原文**：闸名、故事都含答案线索，只能在答对后作为「老周说」出现
- **记录单向追加**：`S.recs` 永不覆盖，因为同一点位的时间序列是产品的北极星指标
- **照片只存内存**：dataURL 不写 localStorage（避免配额爆炸），只存 `has` 标记
- 所有 `render*Mod()` 必须有 `if(!box) return` 保护——结构改动后极易漏引用

## 记录模型

统一对象，8 个字段：

```js
{
  id, gateId, ts, type,
  obs,        // [{key, num, unit, txt}]  ← 没有它，产品就只是问卷
  evidence,   // {has, photo}
  env, observer, license,
  source,     // 'field' 进数据集 / 'explore' 只科普
  label, note, pts, seed
}
```

`obs` 是核心：`num` 可统计，`txt` 是人的话。
两个派生视图：按点位聚合（足迹图 / 站点详情）、按时间排序（时间线 / 同项对比）。

## 路线图

| 阶段 | 周期 | 过闸条件 |
|---|---|---|
| **P0 变真** | 2 周 | 5 个真孩子中 4 人能独立完成含有效数值的记录 |
| **P1 单点闭环** | 6 周 | D30 复访率 ≥40%，且 1 个点位有 ≥10 条跨时间同项记录 |
| **P2 数据可见** | 8 周 | 有机构把数据真的用进某份材料 |
| **P3 复制** | Q2 起 | 第二条河上线且不依赖原团队驻场 |

**北极星**：同点位有效记录数。

**护栏**：单条记录 ≤4 分钟、定位失败率 ≤15%、跨站完成率不作 KPI、照片上传 ≥60%。
